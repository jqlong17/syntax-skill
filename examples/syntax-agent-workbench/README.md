# Syntax Agent Workbench

这是 `syntax-skill` 的可运行 Next.js 实战参考：左侧包含由 `src/app/agent-state.json` 驱动的认知流程状态图和业务认知图谱，右侧是可以通过结构化 patch 更新页面的 AI 助手。

## 启动

```bash
pnpm install
pnpm dev
```

然后打开终端显示的本地地址。

## 使用方式

- 不配置 API Key 时，页面使用本地演示模式；输入“记忆”或“验证”即可看到结构焦点更新。
- 点击“连接设置”，填写 OpenAI-compatible API Base URL、API Key 和模型名称。
- 默认 Base URL 是 `https://api.aixhan.com/v1`，默认模型是 `gpt-5.5`，但项目不会预置任何 API Key。
- 模型下拉菜单支持 `gpt-5.5`、`gpt-6-astra`、`gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna` 和 `gpt-5.2`。
- 页面默认使用中文，右上角可以切换到英文界面。
- 左侧可以切换“认知流程”和“业务认知图谱”两个视图；业务图谱会随对话新增或更新实体、对象类型和关系。
- 图谱支持拖拽节点、拖动空白区域平移、鼠标滚轮缩放，以及按关系层级自动布局。
- 模型需要返回 JSON：

```json
{
  "reply": "给用户看的说明",
  "patch": {
    "focus": "可恢复记忆",
    "summary": "新的结构摘要",
    "nodes": [
      {
        "id": "memory",
        "status": "in_progress",
        "detail": "当前处理的内容",
        "confidence": 0.82
      }
    ],
    "entities": [
      { "id": "order", "name": "订单", "type": "业务对象", "detail": "当前请求相关的业务对象", "confidence": 0.92 }
    ],
    "relations": [
      { "id": "user-creates-order", "source": "user", "target": "order", "type": "创建", "confidence": 0.9 }
    ],
    "unresolved": ["仍需人工确认的业务规则"]
  }
}
```

前端只允许模型更新已有流程节点；业务图谱允许新增或更新当前请求直接相关的实体和关系，但会校验关系两端是否存在。真实项目应进一步加入服务端代理、权限校验、工具执行和独立验证器。

## 与 Onto 本体的关系

这个示例里的“业务认知图谱”是对话阶段的中间表示，不应直接等同于 Onto 的正式本体库：

| 本示例 | Onto 正式模型 | 含义 |
| --- | --- | --- |
| `entities` | 对象类型候选或对象实例候选 | 模型从对话中抽取的实体，目前只带名称、类型、描述和置信度 |
| `relations` | 链接类型候选或链接实例候选 | 模型提出的关系，尚未完成 schema 校验、主键绑定和写回 |
| `nodes` | Agent 的任务状态 | 表达当前要做什么、依赖什么、是否已验证，不属于业务本体实体层 |

Onto 中的**对象类型**是 schema：定义对象编码、属性、主键、来源和能力形态，例如 `Facility`、`Person`。**对象实例**是具体数据记录：通过 `typeId` / `objectTypeCode` 指向对象类型，并携带名称、属性、空间、时间和证据。类似地，**链接类型**定义允许连接哪两类对象及基数，**链接实例**才是某两个具体对象实例之间的一条事实关系。

因此，推荐的生产落地链路是：

```text
对话实体 → 候选对象类型 / 候选对象实例 → 主键与属性校验 → Onto 对象实例
对话关系 → 候选链接类型 / 候选链接实例 → 两端类型与基数校验 → Onto 链接实例
```

本示例当前停留在“候选认知图”层，适合让 Agent 组织上下文、提出结构化变更和等待人工确认；真正写入 Onto 前，还需要补充对象类型匹配、实例唯一性、属性映射、证据来源、权限和审计版本。

## 安全边界

API Key 仅保存在当前浏览器的 `localStorage`，不会写入仓库。使用第三方中转 API 时，应确认其 CORS、日志、计费和数据保留政策；生产环境建议使用服务端代理或短期令牌。
